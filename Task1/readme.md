# Аудит мер по обеспечению безопасности данных

В компании очень низкий уровень работы с конфиденциальными данными.
В качестве конфиденциальных данных выступают персональные данные, медицинские данные.
Данные не имеют классификации и В ИТ-контуре отсутствуют ролевые модели для доступа к данным, что
не позволяет как-то разделить\ограничить доступы к данным.
Всё это несёт большие риски для компании в случае утечки или порче конфиденциальных данных.
Что несёт, как репутационные издержки, так и штрафные санкции от регулятора за несоблюдение 152-ФЗ

# Проблемные зоны:

 - Много персональных и медицинских данных лежит в открытом виде, в общедоступных сетевых папках, в виде обычных Excel файлов.
 - Нет защиты самих данных от кражи или изменения: нет ограничений по доступу, данные не зашифрованы.
 - Не мониторится изменения данных, на случай их порчи.
 - Отстутствует механизм классификации данных
 - Отстутствует ролевая модель с разграничением прав доступа
 - Для аналитики используются данные, содержащие конфиденциальную информацию в необезличенном виде.

# Предлагаемые улучшения

## Список данных для защиты

 - Персональные и медицинские данные можно шифровать при хранении:
    - ФИО пациента, контактные данные
    - Медицинские данные:
        - Результаты анализов
        - Назначенное лечение
    - Данные сотрудников в 1С тоже можно шифровать.
        - Шифровать файловую БД
 - Эти же данные при передаче в аналитику необходимо дешифровать и обезличить.

## Механизм тегирования данных

Для тегирования предлагается использовать систему BigID.
BigID — это интеллектуальная платформа для идентификации, классификации и управления данными

  - Сканирует ВСЕ источники данных:
    * Базы данных (SQL, NoSQL)
    * Data lakes (Hadoop, S3, Azure)
    * Файловые хранилища
    * SaaS-приложения (Salesforce, Office 365)
  
  - Автоматически определяет типы данных:
    * PII (Персональные данные): паспорта, телефоны, emails
    * Финансовые данные: счета, транзакции
    * Медицинские данные: диагнозы, истории болезней
    * Конфиденциальная информация: пароли, ключи

Его преимущества:
 - Масштабируемость и скорость
│ Метод           │ Время на 1 ТБ    │ Точность        │
|||
│ Ручной анализ   │ 3-6 месяцев      │ 60-70%          │
│ DLP-системы     │ 2-4 недели       │ 75-85%          │
│ BigID           │ 2-7 дней         │ 95-99%          │

 - Поддержка регуляторных требований
 - Автоматизация 
 - Интеграции 
    - Большое кол-во поддерживаемых систем и форматов данных.

Идеально подходит для больших компаний с серьёзными требованиями к приватности данных.

Так как компания собирается активно расширяться, и в компании используются медицинские данных для которых очень большие требования к приватности, это решение выглядит подходящим.

Минусы:
 - Сложность в первоначальной настройке. ML может ошибаться, нужная точная настройка.
 - Нужны большие ресурсы для работы

## Инструменты, способы и меры для обеспечения конфиденциальности данных

 - Внедрить BigID для систематицазии и классификации данных
 - Внедрить ролевую модель для доступа к данным, RBAC.
 - Внедрить шифрование чувствительных данных. Дисков и файлов.
 - Настроить механизм обезличивания данных для нужд аналитики.
 - Разработать бизнес-процессы по политикам хранения и удаления конфиденциальных данных.
 - Провести обучение персонала по работе с конфиденциальными данными.
